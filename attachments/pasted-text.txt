COUR — PRODUCTION BLUEPRINT

Reference-led recreation of the supplied interactive clothing experience

I inspected the supplied mobile recording frame-by-frame and cross-checked the visible reference against the currently published reference listing. The reference is “Artefakt” on Templify, described as a near-black outerwear experience with a cursor-reactive lattice, an iridescent jacket moving between screen states, trailing sleeve motion, and technical labels resolving from static; the published listing identifies the template as landing page / Three.js / Next.js. 

One important distinction: the recording exposes the public visual and interaction layer, not the original private database, API implementation, authentication system, server logic, or source code. The reference page itself indicates the source is gated, so those internals cannot honestly be claimed as known. 

Therefore this blueprint defines a pixel-accurate recreation of the observable experience, while rebuilding the hidden production stack as a clean, maintainable equivalent.

Motion physics

The Three.js object should never instantly snap to the pointer.

Use:

targetRotation
        ↓
lerp / damp
        ↓
currentRotation

with separate response coefficients for:

body

left sleeve

right sleeve

secondary accessory geometry


This produces the characteristic “turning to your hand / trailing behind” behavior described by the reference.

==================================================
VEO-GENERATED ASSETS
If cinematic assets were generated through Veo or another model:
Do NOT reference temporary generation URLs in the deployed website.
Persist the accepted video first.
Use the permanent asset URL/path.
If server-side Veo generation is intentionally included as an ADMIN TOOL:
• keep Gemini/API credentials server-side
• require administrator authorization
• show generation progress
• handle long-running operations
• require human approval before replacing live media
• persist accepted output
• do not automatically publish unsuccessful generations
Generated-video creation is optional CMS functionality.
The website itself must not depend on generating footage during normal visitor page loads.
